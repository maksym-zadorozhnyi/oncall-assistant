## Як запустити те, що вже працює

```powershell
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt   # встановити залежності
python -m core.config                       # перевірити .env (перші 4 символи)
python -m core.db                           # створити базу, показати таблиці
python -m core.db --er                      # + перегенерувати docs/er.md
python -m agent.agent --print               # пробний замір ПК, без запису в БД
```

## Відомі проблеми і що відкладено

- **Предметна галузь.** Обрано адаптацію напряму №2 ТЗ (стан обладнання +
  оператор) до серверної. Чекаємо підтвердження викладача.
- **Комп'ютерний нюх (ТЗ 4.2).** Чекаємо відповіді викладача, чи він
  обов'язковий. Якщо так — «датчики повітря серверної» (датасет Smoke
  Detection + симулятор, PCA + Random Forest).
- **Назва ранбука для диска** (`disk-fill.md` чи `iis-log-rotation.md`,
  як очікує крок 3.3) — вирішимо на кроці 3.2.
- **Коди подій в онтології** — чернетка, потрібна ваша перевірка.
  Для `cpu_high`, `site_down`, `cert_expiry` стандартних подій немає:
  їх виявляємо за метриками і перевірками.

- **Реальний ПК близько до порогів:** C: зайнятий на ~80 %, RAM ~88 %.
  Коли на кроці 4.4 агент запрацює постійно, можливі справжні алерти.
- **Агент бачить себе в топі процесів** (`python.exe`) — поки залишено так,
  як у звичайних агентах моніторингу.
